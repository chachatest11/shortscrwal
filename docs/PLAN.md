# ChannelBoard 기획안 — YouTube 다채널 운영 대시보드

작성일: 2026-09-16 · 버전: 1.0 · 상태: 구현 기준 문서

---

## 1. 배경과 목표

여러 개의 YouTube 채널을 동시에 운영하면 채널마다 YouTube 스튜디오를 열어 구독자·조회수·업로드 상태를 확인해야 한다.
채널이 5개만 넘어가도 "어느 채널이 오늘 업로드를 안 했는지", "어느 채널이 이번 주에 빠지고 있는지",
"어떤 영상이 평소보다 잘 나가는지"를 한 번에 파악하기 어렵다.

ChannelBoard는 **YouTube 공식 Data API v3**만으로 운영 중인 모든 채널의 현황을 **한 화면**에 모아 보여주고,
매 갱신마다 통계를 기록해 **변화(증감)와 추이**를 보여주는 로컬 실행형 웹 앱이다.

### 목표
1. 한 화면에서 모든 채널의 핵심 지표(구독자·조회수·영상 수·최근 업로드)와 기간 대비 증감을 본다.
2. 운영자가 바로 행동해야 할 신호(업로드 공백, 구독자 감소, 급상승 영상, 마일스톤 임박)를 자동으로 띄운다.
3. 브라우저를 닫아 둬도 서버가 주기적으로 갱신해 이력이 쌓이게 한다.
4. API 쿼터(일 10,000 units)를 거의 쓰지 않는다. 채널 50개 갱신에 1 unit.
5. 설치가 쉽다. Python + `pip install` + API 키 1개면 끝. 빌드 도구 없음.

### 목표가 아닌 것 (v1)
- 시청 시간·수익·트래픽 소스·유지율 등 **YouTube Analytics API**(채널 소유자 OAuth 필요) 데이터 → v2 후보
- 영상 다운로드, 업로드, 댓글 관리 등 채널 조작 기능
- 다중 사용자 / 로그인 (개인 로컬 도구로 설계)

## 3. 사용자와 핵심 시나리오

**대상**: 채널 3~100개를 운영하는 개인 또는 소규모 팀. YouTube API 키를 만들 수 있는 정도의 기술 수준.

| 시나리오 | 원하는 답 | 화면 |
|---|---|---|
| 아침에 앱을 연다 | 어젯밤 이후 어느 채널이 얼마나 늘었나, 업로드 안 한 채널은? | 대시보드 (24시간) |
| 주간 점검 | 7일간 채널별 구독자/조회수 증감 순위, 급상승 영상 | 대시보드 (7일) + 정렬 |
| 특정 채널이 이상하다 | 일별 증감표, 구독자 추이 그래프, 최근 영상 성과 | 채널 상세 |
| 새 채널을 만들었다 | URL 하나 붙여넣고 그룹에 넣는다 | 채널 관리 → 채널 추가 |
| 어떤 영상이 잘 되나 | 전체 채널의 영상을 조회수/일, 최근 증가로 정렬 | 영상 |
| 키 쿼터가 걱정된다 | 오늘 얼마나 썼는지, 키 여러 개 자동 교대 | 설정 → API 키 |

## 4. 기능 범위 (MoSCoW)

### Must
- 채널 등록: 채널 URL / @핸들 / 채널 ID / `/c/`·`/user/` URL / **영상 URL**(해당 채널로 변환), 여러 줄 일괄 입력
- 그룹: 채널을 그룹으로 묶기 (예: 내 채널, 서브 채널, 참고 채널), 그룹별 필터
- 갱신: 수동("지금 업데이트") + 서버 자동 갱신(1/3/6/12/24시간), 진행률 표시
- 채널 통계 스냅샷 저장 → 기간(24시간/7일/30일/90일) 대비 증감, 30일 추이
- 최근 영상 수집(채널당 N개) → 기간 내 업로드 수, 최신 영상, 영상별 조회수/좋아요/댓글
- 대시보드: KPI 타일, 인사이트(업로드 공백·구독자 감소·급상승 영상·마일스톤), 채널 표, 최근 업로드 피드
- 채널 상세: KPI, 구독자 추이 차트, 일별 조회수 증가 차트, 일별 증감표, 최근 영상 표, 메모
- 영상 탐색: 그룹/채널/기간/유형(쇼츠·롱폼) 필터, 조회수·조회수/일·최근 증가·게시일 정렬, 검색
- API 키 여러 개 등록, 쿼터 초과 시 자동 교대, 오늘 사용량 표시, 쿼터일(태평양 시간) 자동 초기화
- 라이트/다크 테마, 모바일 대응
- CSV 내보내기(채널 현황, 영상)

### Should
- 급상승 판정: 채널 평소(최근 90일 영상의 조회수/일 중앙값) 대비 배수 표시
- 온보딩 체크리스트(API 키 → 채널 추가 → 첫 갱신)
- 이전 버전(쇼츠 수집기) DB에서 채널·그룹·API 키 자동 가져오기

### Could (v2)
- YouTube Analytics API(OAuth) 연동: 시청 시간, 수익, 트래픽 소스
- 알림(텔레그램/슬랙/이메일): 업로드 공백, 급상승
- 영상별 조회수 이력 차트

### Won't (v1)
- 영상 다운로드 / 업로드, 댓글 관리, 다중 사용자

## 5. 정보 구조 (IA)

```
ChannelBoard
├─ 대시보드 (#/)                 전체 현황 · 인사이트 · 채널 표 · 최근 업로드
├─ 채널 관리 (#/channels)        목록 · 추가 · 그룹 · 일괄 작업 · CSV
│   └─ 채널 상세 (#/channels/:id) KPI · 차트 · 일별 증감 · 영상 · 메모
├─ 영상 (#/videos)               전체 채널 영상 탐색
└─ 설정 (#/settings)             API 키 · 자동 갱신 · 데이터 · 테마
```

공통 셸: 좌측 사이드바(내비게이션, 오늘 쿼터 사용량, 테마 전환) + 상단 바(페이지 제목, 마지막 갱신 시각, "지금 업데이트").
모바일에서는 사이드바가 접히고 햄버거 버튼으로 연다.

## 6. 화면 설계

### 6.1 대시보드
1. **필터 행**: 기간(24시간 · 7일 · 30일 · 90일 세그먼트) · 그룹 선택 · 채널 검색. 아래 모든 숫자는 이 필터를 따른다.
2. **온보딩 카드** (조건부): API 키 없음 / 채널 없음 / 아직 갱신 안 함 단계별 안내와 버튼.
3. **KPI 타일 5개**: 채널 수 · 총 구독자(±기간) · 총 조회수(±기간) · 총 영상(±기간) · 기간 내 업로드(업로드 없는 채널 n개).
4. **인사이트 카드**(좌) — 각 항목은 아이콘 + 문장 + 바로가기
   - 업로드 공백: N일 이상 업로드 없는 채널 (임계값 설정 가능, 기본 7일)
   - 구독자 감소: 기간 내 구독자가 줄어든 채널
   - 급상승 영상: 채널 평소 대비 1.75배 이상 조회수/일, 또는 최근 갱신 간 조회수 증가 상위
   - 마일스톤 임박: 다음 라운드 숫자(1천/1만/10만/100만…)까지 5% 이내
   - 오늘 업로드: 24시간 내 업로드한 채널
5. **최근 업로드 피드**(우): 전체 채널 최신 영상 8개 (썸네일 · 채널 · 경과 시간 · 조회수 · 쇼츠 배지)
6. **채널 표**: 채널(아바타·이름·그룹) · 구독자(±) · 조회수(±) · 영상(±) · 기간 업로드 · 최근 업로드(상태 배지) · 30일 추이 스파크라인. 헤더 클릭 정렬, 행 클릭 → 상세, 첫 열 고정, 가로 스크롤.

### 6.2 채널 상세
- 헤더: 아바타 · 채널명 · @핸들 · 그룹 · 국가 · 개설일 · 버튼(YouTube 열기, 스튜디오 열기, 그룹 변경, 활성/비활성, 삭제)
- KPI: 구독자(±) · 조회수(±) · 영상 수(±) · 기간 업로드 · 영상당 평균 조회수(기간)
- 차트(기간 7/30/90일): ① 구독자 추이(선) ② 일별 조회수 증가(막대). 이중 축 금지 → 두 개의 차트
- 일별 증감표: 날짜 · 구독자 · 증감 · 조회수 · 증감 (Social Blade 방식, 초록/빨강)
- 최근 영상 표: 썸네일·제목 · 게시일 · 조회수 · 조회수/일 · 최근 증가 · 좋아요 · 댓글 · 길이/쇼츠
- 메모(자유 텍스트, 자동 저장)

### 6.3 채널 관리
- 도구 모음: 그룹 필터 · 검색 · [채널 추가] · [그룹 관리] · [CSV]
- 표: 체크박스 · 채널 · 그룹(인라인 선택) · 구독자 · 활성 토글 · 마지막 갱신 · [상세] [삭제]
- 선택 시 일괄 바: 그룹 이동 · 활성 · 비활성 · 삭제
- 채널 추가 모달: 여러 줄 입력(URL/@핸들/ID/영상 URL 혼합 가능) · 그룹 선택 · 결과 목록(성공/실패 사유)
- 그룹 관리 모달: 추가 · 이름 변경 · 순서 · 삭제(채널은 기본 그룹으로 이동)

### 6.4 영상
- 필터: 그룹 · 채널 · 기간(게시일) · 유형(전체/쇼츠/롱폼) · 정렬 · 검색
- 표: 썸네일·제목 · 채널 · 게시일 · 조회수 · 조회수/일 · 최근 증가 · 좋아요 · 댓글 · 길이 · 평소 대비 배수
- 50개씩 "더 보기"

### 6.5 설정
- API 키: 목록(마스킹 · 이름 · 상태 · 오늘 사용량 · 마지막 사용) · 추가 · 삭제 · 쿼터 상태 초기화
- 자동 갱신: 사용 여부 · 주기(1/3/6/12/24시간) · 채널당 최근 영상 수(5~50) · 조회수 재수집 대상 기간(30/90/180일) · 업로드 공백 기준일 · 다음 실행 예정
- 데이터: DB 위치·크기, 스냅샷 수, 이전 버전 데이터 가져오기, 갱신 기록(최근 20회)
- 외관: 테마(시스템/라이트/다크)

## 7. 디자인 원칙 (시인성 · 직관성)

- **숫자가 주인공**: 값은 굵고 크게, 라벨은 작고 흐리게. 표의 숫자는 `tabular-nums`로 자리 맞춤.
- **증감은 색 + 기호 + 텍스트**: ▲ +1,204 / ▼ −38. 색만으로 의미를 전달하지 않는다(색약 대응).
- **상태 배지는 아이콘 + 문구**: 24시간 내 업로드(초록), 7일째 업로드 없음(주황), 수집된 영상 없음(회색).
- **한 줄 필터 행**이 아래 모든 내용의 범위를 정한다. 카드 안에 개별 필터를 두지 않는다.
- **재조회 중에는 이전 화면을 유지**하고 흐리게만 처리한다(레이아웃 점프 없음).
- **차트는 얇게**: 2px 선, 10% 면적 채움, 하나의 축, 헤어라인 그리드, 크로스헤어 툴팁. 단일 시리즈에는 범례 없음.
- **한국어 숫자 표기**: 1만 미만은 1,234, 그 이상은 15.2만 / 8,690만 / 1.2억. 전체 값은 툴팁으로.
- **라이트 기본 + 다크 지원**, 시스템 설정 따름. 두 모드 모두 대비 4.5:1 이상의 텍스트.
- **빈 상태는 다음 행동을 알려준다**: "채널이 없습니다 → [채널 추가]".
- 글꼴: Pretendard(있으면) → 시스템 산세리프.

## 8. 데이터 모델 (SQLite)

```
groups            id, name, sort_order, created_at
channels          id, youtube_id(UNIQUE), title, handle, description, thumbnail_url, country,
                  published_at, uploads_playlist_id, group_id(FK), is_active, memo,
                  subscriber_count, subscriber_hidden, view_count, video_count,
                  stats_updated_at, created_at, updated_at
snapshots         id, channel_id(FK), subscriber_count, view_count, video_count, captured_at
                  (최근 2일은 전부 보관, 이후는 채널별 하루 마지막 1개만 보관)
videos            id, channel_id(FK), youtube_id(UNIQUE), title, published_at, duration_seconds,
                  is_short, thumbnail_url, view_count, like_count, comment_count,
                  view_count_prev, stats_prev_at, stats_updated_at, first_seen_at
api_keys          id, api_key(UNIQUE), name, is_active, quota_exceeded, quota_exceeded_at,
                  used_today, used_date, last_used_at, created_at
settings          key, value
refresh_runs      id, started_at, finished_at, status, scope, channels_total, channels_updated,
                  videos_updated, quota_used, error
```

채널은 YouTube 채널 ID 기준으로 **하나만** 존재하고 그룹은 하나만 가진다(이전 버전의 카테고리별 중복 저장 폐지).

## 10. 갱신 엔진과 쿼터 전략

1. 대상 채널(활성) 로드 → `channels.list`를 50개씩 배치 호출(배치당 1 unit) → 채널 통계 갱신 + 스냅샷 저장
2. 채널별 `playlistItems.list`(1 unit)로 최근 업로드 N개 ID 수집
3. 새 영상 + "재수집 대상 기간" 내 기존 영상 ID를 모아 `videos.list` 50개씩(배치당 1 unit) → 조회수/좋아요/댓글 갱신, 이전 값은 `view_count_prev`에 보관(속도 계산용)
4. 스냅샷 압축, 실행 기록 저장, 키별 사용량 저장

예: 채널 30개, 채널당 최근 10개, 재수집 90일 영상 300개 → 1 + 30 + 6 ≈ **37 units** / 회. 6시간마다 돌려도 하루 150 units.

키 관리: 활성 키를 우선순위대로 사용, `quotaExceeded`(403) 응답이 오면 그 키를 "쿼터 초과"로 표시하고 다음 키로 이어서 진행.
쿼터일은 태평양 시간 자정에 초기화되므로 날짜가 바뀌면 사용량과 초과 표시를 자동 리셋한다.
`search.list`(100 units)는 `/c/커스텀URL` 해석에만 예외적으로 사용하고 UI에 비용을 알린다.

자동 갱신: 서버 시작 시 백그라운드 루프가 1분마다 "마지막 성공 + 주기 ≤ 지금"인지 확인해 실행한다. 동시 실행은 잠금으로 막는다.

## 11. 인사이트 계산 규칙

| 인사이트 | 규칙 |
|---|---|
| 업로드 공백 | 최신 영상 게시 후 `stale_days`(기본 7) 이상 경과, 또는 수집된 영상 없음 |
| 구독자 감소 | 기간 시작 스냅샷 대비 구독자 감소 |
| 급상승 영상 | (a) 채널 최근 90일 영상들의 "조회수/일" 중앙값 대비 1.75배 이상 (표본 3개 이상일 때) 또는 (b) 최근 두 갱신 사이 조회수 증가 상위 5개 |
| 마일스톤 임박 | 구독자가 다음 라운드 숫자(1천·5천·1만·5만·10만·50만·100만·…)의 95% 이상 |
| 오늘 업로드 | 24시간 내 게시 영상이 있는 채널 |

"조회수/일" = 조회수 ÷ max(게시 후 경과일, 1/24). 너무 어린 영상의 왜곡을 줄이기 위해 급상승 판정은 게시 후 12시간 이상 지난 영상만 대상으로 한다.

## 12. 기술 스택과 구조

- 백엔드: Python 3.9+, FastAPI, SQLite(표준 라이브러리), requests. 빌드 도구 없음.
- 프론트엔드: 정적 HTML + ES 모듈 바닐라 JS(해시 라우터 SPA) + CSS 변수 디자인 토큰. 차트는 Chart.js 4(MIT, 저장소에 동봉).
- 테스트: pytest + FastAPI TestClient + 가짜 YouTube API 응답. UI는 Playwright 스크린샷으로 확인.

```
app/
  main.py            FastAPI 앱, 정적 파일, 라이프사이클(스케줄러)
  config.py          경로·상수
  db.py              스키마·마이그레이션·연결
  services/          youtube(API 클라이언트·키 교대), resolver(입력→채널), refresh(갱신 엔진),
                     insights, scheduler, legacy_import
  routers/           overview, channels, groups, videos, refresh, keys, settings, export
  static/            index.html, css/(tokens·base·components·views), js/(app·router·api·ui·charts·views/), vendor/chartjs
docs/PLAN.md         이 문서
tests/               pytest
data/app.db          런타임 DB (git 제외)
```

## 13. 이전 버전에서 달라지는 점

| 이전 (쇼츠 수집기) | ChannelBoard |
|---|---|
| 다른 채널의 쇼츠를 모아 다운로드 | 내 채널들의 현황·추이·신호를 본다 (참고 채널도 그룹으로 등록 가능) |
| 카테고리별로 같은 채널 중복 저장 | 채널은 하나, 그룹은 하나 |
| 브라우저를 열어야 갱신 | 서버 자동 갱신 |
| 쿼터 초과 시 중단, 수동 초기화 | 키 자동 교대, 날짜 바뀌면 자동 초기화 |
| 다크 단일 테마, 한 페이지 | 라이트/다크, 5개 화면, 모바일 대응 |
| yt-dlp 다운로드 | 제거 (범위 밖) |

기존 `app/database.db`가 있으면 첫 실행 때 채널·카테고리(→그룹)·API 키·스냅샷을 자동으로 가져온다.
